## 6. ШЛЮЗИ (Gateways) - ПРАВИЛА РОЗГАЛУЖЕНЬ

### 6.1 Шлюз Екскдюзивного Вибору (XOR Gateway)
```
Питання: Маєш рахунок?
├─ ДА  → Процес входу (login)
└─ НІ  → Процес реєстрації (register)

Використовується для однозначного вибору одного з можливих шляхів
```

### 6.2 Шлюз Паралельної Обробки (AND Gateway)
```
Перед обробкою покупки необхідно:
├─ Валідація запису клієнта
├─ Перевірка доступності місць
└─ Перевірка корректності ціни

ВСІ три умови повинні бути виконані перед продовженням
```

### 6.3 Шлюз Повторного З'єднання (Merging Gateway)
```
Результати з різних шляхів:
├─ Якщо місця вільні → Додавання до кошика
├─ Якщо місця займ.  → Помилка (повтор вибору)
└─ Обидва шляхи збігаються для розрахунку
```

## 8. ТАЙМЕРИ ТА ПОМИЛКИ (Error Handling)

### 8.1 Помилки Валідації
```
Контрольні точки:
├─ DNI не валідна → Помилка, повтор введення
├─ Email має невірний формат → Помилка, повтор введення
├─ Пароль занадто короткий → Помилка, повтор введення
├─ Email вже існує в БД → Помилка, пропозиція входу
└─ Місця займані → Помилка, повтор вибору місць
```

### 8.2 Таймери та Тайм-аути
```
Резервування місць:
├─ Місця блокуються на 15 хв під час вибору
├─ При відсутності дії - автоматичне скасування
└─ Звільнення місць для інших користувачів
```

### 8.3 Компенсаційні Дії (Compensation)
```
При скасуванні покупки:
├─ Звільнення зарезервованих місць
├─ Повернення коштів (якщо оплачено)
├─ Видалення записи з БД
└─ Очистка тимчасових даних
```

## 9. ПОСЛІДОВНІСТЬ ДАНИХ (Data Objects)

```
1. ВХІДНІ ДАНІ:
   ├─ Дані клієнта: {DNI, email, password, ПІБ}
   ├─ Вибір: {фільм, дата, час сеансу}
   ├─ Бронювання: {місця, кількість}
   └─ Оплата: {сума, метод}

2. ПРОМІЖНІ ДАНІ:
   ├─ Сеанс: {id, sala_id, precio, asientos_disponibles}
   ├─ Кошик: {sesiones[], cantidades[], descuento}
   ├─ Резервування: {session_id, asientos[], estado="blocked"}
   └─ Квитанція: {sesiones, total, iva, descuento}

3. ВИХІДНІ ДАНІ:
   ├─ Квиток: {ticket_id, cliente_id, sesion_id, asientos, fecha}
   ├─ Облік: {ticket_id, cliente_id, total, fecha_compra}
   ├─ Підтвердження: {confirmacion, numero_operacion}
```

## 11. ОБМЕЖЕННЯ ТА КОНФЛІКТИ (Constraints)

### 11.1 Функціональні Обмеження
```
├─ Макс кількість місць на покупку: залежить від залу
├─ Макс кількість сеансів в кошику: не обмежено
├─ Мін. вартість покупки: 1 квиток
├─ Макс. вартість покупки: залежить від сеансів
└─ Час доступності: тільки під час роботи кінотеатру
```

### 11.2 Конфлікти (Race Conditions)
```
Потенціальні проблеми:
├─ Два користувачі обирають один об'єкт одночасно
│  → Розв'язання: Блокування на рівні БД
│
├─ Двійна оплата
│  → Розв'язання: Транзакції (atomicity)
│
├─ Нестійкість даних
│  → Розв'язання: Шифрування паролів,验ификация
│
└─ Перевитрати ресурсів БД
   → Розв'язання: Кеш, оптимізація запитів
```

## 12. АЛЬТЕРНАТИВНІ СЦЕНАРІЇ

### Сценарій A: Успішна Покупка
```
Передумови: Клієнт аутентифікований
Основні кроки:
1. Вибір фільму та сеансу
2. Вибір місць
3. Розрахунок вартості
4. Прийняття умов
5. Оплата (успішно)
6. Видання квитків
Результат: Клієнт отримує квитки, покупка записана
```

### Сценарій B: Скасування Покупки
```
Передумови: Клієнт у процесі вибору
Основні кроки:
1. Клієнт натискає "Скасувати"
2. Системи звільняє зарезервовані місця
3. Кошик очищається
4. Повернення до меню
Результат: Резервування скасовано, місця доступні
```

### Сценарій C: Помилка Валідації
```
Передумови: Клієнт вводить невірні дані
Основні кроки:
1. Система виявляє помилку
2. Виведення повідомлення про помилку
3. Пропозиція повторного введення
4. Залишення на тій самій сторінці
Результат: Клієнт коригує дані
```

### Сценарій D: Критична Помилка БД
```
Передумови: БД недоступна
Основні кроки:
1. Система виявляє розрив з'єднання
2. Виведення повідомлення про помилку
3. Логування помилки
4. Пропозиція повторної спроби
5. Якщо невдача - вихід з системи
Результат: Система безпечно закривається
```
