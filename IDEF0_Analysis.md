## ДЕТАЛЬНІ ФУНКЦІОНАЛЬНІ БЛОКИ (IDEF0 А1-А6)

### **А1: Керування обліковими записами клієнтів**

```
Вхід:
- Дані клієнта (ім'я, прізвище, DNI, email)
- Пароль (у відкритому вигляді)
- Запит на реєстрацію або вхід

Управління:
- Правила валідації DNI та email
- Вимоги до паролю
- Правила шифрування AES
- Правила перевірки унікальності

Механізм:
- ControladorDB
- ClienteAcesso
- ControladorEntradaYSalida

Вихід:
- Підтверджений облік клієнта
- Шифрований пароль
- ID клієнта в БД
- Статус аутентифікації
```

**Процес:**

1. Клієнт обирає реєстрацію або вхід
2. Введення даних
3. Валідація формату DNI та email
4. Перевірка унікальності в БД
5. Шифрування пароля (AES)
6. Збереження або вхід в систему

---

### **А2: Керування каталогом фільмів та сеансів**

```
Вхід:
- Запит на перегляд фільмів
- Вибір дати
- Фільтр за жанром/тривалістю

Управління:
- Формат представлення фільмів
- Правила фільтрування
- Правила доступности по датам

Механізм:
- Таблиці БД (películas, sesiones, salas)
- ControladorDB
- GestorCine

Вихід:
- Список фільмів на вибрану дату
- Інформація про сеанси
- Доступні місця по сеансах
- Інформація про ціни
```

**Процес:**

1. Отримання поточного каталогу з БД
2. Фільтрування за датою
3. Формування списку сеансів
4. Перевірка доступності місць
5. Вивід інформації про ціни та расклад

---

### **А3: Керування кошиком та придбанням квитків**

```
Вхід:
- Вибір сеансу
- Кількість квитків
- Перевірка кошика

Управління:
- Правила розрахунку цін
- Правила застосування знижок
- Правила розрахунку ПДВ (21%)

Механізм:
- Carrito
- Класи Sesion, Pelicula
- GestorTicket

Вихід:
- Квитки (генеровані)
- Квитанція з деталями
- Оновлена інформація про місця
- Облікові записи покупок
```

**Процес:**

1. Додавання сеансу в кошик
2. Введення кількості місць
3. Додавання до кошика (до 3+ сеансів для знижок)
4. Розрахунок вартості (ціна × кількість)
5. Застосування знижок за обсягом
6. Розрахунок ПДВ
7. Формування квитанції

---

### **А4: Керування місцями в залах та сеансах**

```
Вхід:
- Інформація про залу
- Обрані місця
- Іформація про сеанс

Управління:
- Правила розподілу місць
- Правила резервування
- Таблиці місцеположення

Механізм:
- Таблиця Sala в БД
- EspectadoresSesion
- ControladorDB

Вихід:
- Оновлена матриця місць
- Підтвердження резервування
- Статус займаних місць
```

**Процес:**

1. Отримання плану залу
2. Перевірка доступних місць
3. Резервування обраних місць
4. Оновлення БД
5. Блокування місць для інших користувачів

---

### **А5: Керування системою розрахунків знижок**

```
Вхід:
- Кількість сеансів у кошику
- Загальна вартість
- Політика знижок

Управління:
- Знижка 20% для 2 сеансів
- Знижка 30% для 3+ сеансів
- Правила накопичення знижок

Механізм:
- Класи Carrito
- Алгоритми розрахунку
- ControladorDB (для історії знижок)

Вихід:
- Розмір знижки
- Вартість після знижок
- Деталі застосованих знижок
```

**Логіка знижок:**

```
Кількість сеансів = 1 → Знижка = 0%
Кількість сеансів = 2 → Знижка = 20%
Кількість сеансів ≥ 3 → Знижка = 30%

Формула: Вартість після знижки = Вартість × (1 - Знижка/100)
Фінальна ціна = Вартість після знижки × 1.21 (ПДВ)
```

---

### **А6: Видання квитків та облікування**

```
Вхід:
- Облікований кошик
- Підтверджена покупка
- Данні покупця

Управління:
- Формат квитка
- Правила нумерування
- Правила зберігання файлів

Механізм:
- GestorTicket
- Ticket
- Файлова система (compras.txt)

Вихід:
- Сформований квиток
- Облікова запись у файлі
- Підтвердження покупки
```

**Процес:**

1. Вибір опції придбання "Купити"
2. Переведення витрат
3. Генерування об'єкта Ticket
4. Запис у файл compras.txt
5. Вивід квитків на екран/друк
6. Очистка кошика

## ЗАКЛАДКА ОБМЕЖЕНЬ (Constraints)

1. **Безпека:** Паролі шифруються з використанням AES
2. **Валідація:** DNI та email перевіряються на унікальність
3. **Обмеження місць:** Максимум 2-3 особи на місце (залежно від залу)
4. **Система знижок:** Прогресивна система на основі обсягу
5. **ПДВ:** Автоматично застосовується 21% до всіх операцій
6. **Резервування:** Місця блокуються на час вибору

## ВИСНОВОК

Система CineTick розроблена як класичний MVC додаток з чіткою розподілом обов'язків:

- **Контролери** керують бізнес-логікою та БД
- **Модель** представляє дані предметної області
- **Вид** забезпечує текстовий інтерфейс для користувача
- **Сховища** утримують дані клієнтів, фільмів, сеансів та квитків

IDEF0 моделювання показує, що система має добре визначені функціональні блоки з ясними входами, виходами, управління та механізмами.
