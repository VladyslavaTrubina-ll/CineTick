## РЕЗЮМЕ ПРОЕКТУ

**Назва:** CineTick - Система управління продажем квитків кінотеатру  
**Архітектура:** MVC (Model-View-Controller)  
**Технологія:** Java + MySQL  
**Версія:** 1.0  
**Статус:** Робочий прототип

---

## 1. ВИСОКА-РІВНЕВИЙ ОГЛЯД (High-Level Overview)

### 1.1 Призначення системи

Система призначена для управління процесом продажу квитків кінотеатру в консольному середовищі. Вона дозволяє клієнтам:

- Реєструватися та входити в систему
- Переглядати доступні фільми та сеанси
- Обирати місця в залі
- Формувати кошик з кількох сеансів
- Отримувати автоматичні знижки на основі обсягу
- Розраховувати вартість з ПДВ
- Отримувати квитки

### 1.2 Ключові гравці (Stakeholders)

| Гравець           | Роль       | Цілі                              |
| ----------------- | ---------- | --------------------------------- |
| **Клієнт**        | Користувач | Купити квитки зі знижками         |
| **Адміністратор** | Оператор   | Керувати розкладом та продажами   |
| **Кінотеатр**     | Власник    | Максимізувати доход               |
| **Система**       | Провайдер  | Забезпечити безпеку та надійність |

## 7. КРИТИЧНІ ШЛЯХИ (Critical Paths)

### Шлях A: Успішна Покупка (без помилок)

```
Час: ~15 хв
Операції: 12
├─ Реєстрація (2 хв) - валідація + запис
├─ Вхід (30 сек) - перевірка + завантаження
├─ Перегляд каталогу (3 хв) - фільтрування
├─ Вибір сеансу (1 хв) - отримання інформ.
├─ Вибір місць (2 хв) - вибір + блокування
├─ Додавання до кошика (30 сек) - обновления
├─ Розрахунок (5 сек) - формула
├─ Застосування знижок (2 сек) - логіка
├─ Розрахунок ПДВ (1 сек) - × 1.21
├─ Прийняття (30 сек) - конфірм
├─ Видання квитків (3 сек) - генерування
└─ Архівування (1 сек) - запис в файл
```

### Шлях B: Покупка зі знижкою

```
Час: ~20 хв
Операції: 15
├─ Все як у Шляху A, плюс:
├─ Додавання ще 1 сеансу (3 хв)
├─ Додавання ще 1 сеансу (3 хв)
├─ Кожна додавання перезапускає розрахунок
└─ Знижка застосовується до 3-го сеансу
```

### Шлях C: Помилкова Валідація

```
Час: ~10 хв
Операції: 8 + повтор
├─ Введення неправильного DNI
├─ Помилка валідації (1 сек)
├─ Повідомлення про помилку (30 сек)
├─ Повторне введення (2 хв)
├─ Успішна валідація
└─ Продовження нормального процесу
```

## 10. МАТРИЦЯ ВІДПОВІДАЛЬНОСТІ (RACI Matrix)

```
              │ Розроб │ Тест │ Адмін │ Користувач
──────────────┼────────┼──────┼───────┼───────────
Реєстрація    │ R, A   │ C    │ I     │ Виконує

Звіти         │ C      │ –    │ R, A  │ –

R = Responsible (Відповідальний)
A = Accountable (Звітуючий)
C = Consulted (Проконсультований)
```
